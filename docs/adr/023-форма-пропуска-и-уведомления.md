# ADR-023. Кабинет 7b: настройка формы пропуска, правка по этапам, пакет из файла, уведомления

Статус: принято (14.10.2026, этап 7b; дополнено в 7b.1 — раздел «Дополнение 7b.1» ниже). Дополняет ADR-022 (кабинет 7a), ADR-007 (права), ADR-004 (outbox), ADR-020 (UI). Вопросы Q-81–Q-92 — в `QUESTIONS.md`.

## Контекст

Заказчик проверил 7a на стенде с компьютера и с телефона: форма пропуска слишком длинная и показывает лишнее («ФИО и телефон водителя» не нужны); логисту фур нужно «вбил номер → Создать → фура заезжает»; нельзя поправить пропуск; пакет принимает только вставку; решение согласующего не видно без захода в список; на телефоне фильтры занимают пол-экрана.

## Решение

### 1. Форма по уровням «объект → арендатор → сотрудник»

Таблица `pass_form_settings` (`level` = `site`/`tenant`/`user`, `settings jsonb` — только заданные на уровне ключи; пустой уровень не хранится). Разрешение — **чистая функция `resolvePassForm`** в `contracts`: «по умолчанию» → объект → арендатор → сотрудник, ключ за ключом (поля формы — по каждому полю), результат хранит **источник каждого значения** (для подписи «с какого уровня взято»). «Сбросить к уровню выше» — `null` в PATCH (ключ удаляется). Ключи: разрешённые типы транспорта и тип по умолчанию, виды пропусков и вид по умолчанию, режимы полей (марка, ФИО и телефон водителя, окно, место назначения, цель, комментарий), `singleHours`. По умолчанию ФИО и телефон водителя скрыты (код, а не данные).

**Сервер применяет форму тем же кодом** (`pass-form/service.ts`: `assertFormAllows`, `fillDefaults`) в `createPass` (значит, и в пакете, и в «повторить день»), в `patchPass` (проверяются только затронутые поля — поле, ставшее обязательным позже, не мешает поправить комментарий) и в подсказках (`pass-hints` отдаёт уже отфильтрованные типы и виды). Скрытое поле с значением — `field_hidden`, обязательное без значения — `field_required`, чужой тип — `category_unavailable`, чужой вид — `pass_type_forbidden`. Форма **не шире прав роли**: итоговые виды — права `pass.create.*` ∩ политика согласования ∩ форма. Форма ограничивает **пользователей арендатора**; сотрудников оператора — нет (Q-82).

**Исключение из правила «недоступное — неактивным с причиной»** (записано в `CLAUDE.md`, как с договорами): виды пропусков, типы транспорта и поля, которых форма не разрешает, не показываются вовсе — так хочет заказчик. Права по-прежнему проверяются на сервере.

Права: `pass_form.manage` (объект и арендатор — администратор объекта, владелец) и `pass_form.manage_users` (сотрудники своей компании — ещё и «Арендатор — ответственный»); миграция `0012` по шаблонам ролей (ADR-007). Редактор — `/admin/pass-form` и `/cabinet/pass-form`; **живой предпросмотр** рисует ту же `PassFormFields`, что и форма сотрудника, из той же `buildFormView` — поэтому «ровно так, как увидит выбранный сотрудник», включая права его роли (`GET /tenants/:id/pass-form/editor?userId=`). Каждое изменение — в аудит «было → стало» с причиной, событие `pass_form.changed` обновляет открытые формы без F5.

### 2. Быстрый разовый и умные значения

Разовый пропуск без начала и окончания: **начало — «сейчас» по часам сервера, окончание — начало + N ч** (по умолчанию 23, но не больше максимума разового пропуска объекта; настройка уровня `singleHours`, проверка при сохранении). Клиент ничего не считает за сервер: часы браузера и пояс не участвуют; явное «с/до» — в «Ещё». Окно по политике: если политика требует окно, а форма — нет, сервер ставит окно на весь срок (Q-81). Умные значения в форме: единственный тип транспорта, единственное место назначения (пункта «Не указано» нет; две и больше — «Не указано» по умолчанию), единственный нужный док подставляются; тип по умолчанию берётся из формы, потом из арендатора.

### 3. Правка пропуска по этапам и граница с заявками (сценарий 41, A8)

`pass.phase`: **до въезда** — правятся номер, тип, время, место назначения, комментарий (и док — без него нельзя сменить тип на грузовой) с повторной проверкой; **после въезда** (есть открытый визит) — только комментарий и «действует до» (остальное — `pass_phase_locked`); **после выезда или использования** — только просмотр (`pass_not_editable`). У разового «использован» наступает после выезда; многоразовый и постоянный после выезда остаются рабочими и правятся как «до въезда» (следующий въезд). У начавшегося пропуска причина обязательна (сценарий 20).

**Что остаётся заявкой к согласующему**: если пропуск проходил согласование (политика создателя «на согласование» или не задана), пользователь арендатора номер, тип и срок меняет **заявкой на изменение** — пропуск не перевыпускается, действует прежний, история сохраняется (A8); раньше заявка требовалась для любого начавшегося пропуска, из-за чего быстрый разовый нельзя было поправить без администратора. Теперь у пропуска без согласования (разовый по умолчанию) арендатор правит сам. После въезда продление «действует до» у такого пропуска — тоже заявкой, сокращение — сразу (Q-85).

### 4. Пакет: файл, нормализация, исправление в предпросмотре

Файл `.xlsx`/`.csv` (перетащить или выбрать — `FileDrop`, везде, где есть пакетный ввод) превращается в текст «как вставка из Excel», поэтому один разбор строк служит и файлу, и буферу. `.xlsx` читается **без тяжёлой библиотеки**: zip (зависимость `fflate` 0.8.3 — распаковка) + общие строки и первый лист по связям книги; CSV — UTF-8 или windows-1251. Колонки — по заголовку (синонимы «Госномер», «Тип ТС», «Док», «Место»…) или по порядку. Строки живут в состоянии экрана и правятся в предпросмотре: тип, док, место, окно; «применить ко всем без типа / дока / места». Тип распознаётся по основам слов («легковые» → «легковой»); **неоднозначное не угадывается** — строка просит выбрать из подходящих. Колонки, скрытые формой, игнорируются с видимым предупреждением; остальные проверки — те же `createPass` через `dryRun`.

### 5. Уведомления на событиях outbox

События пишутся как раньше; обработчики, зарегистрированные через `onEmit`, выполняются **в той же транзакции** (`Scope.emit`): нет потерянных и дублирующихся уведомлений, тест видит результат сразу. `notifications` (`channel = 'in_app'`, `read_at`, `unique(event_id, user_id, kind, channel)`): планировщики по типам событий (`pass.status_changed` из согласования → одобрено / с изменениями / отклонено с причиной; `pass.change_decided`) → список каналов `CHANNELS`. **Этап 10 добавляет каналы (почта, Telegram, push) записью в `CHANNELS`**, планировщики и тексты не меняются. Текст — снимок на момент события в `notifications.payload` (не в `domain_events`); событие `notification.created` без текста и ПДн видит только адресат (`visibleTo`), поэтому колокольчик обновляется по SSE вместе с остальным. Свои действия не уведомляют.

### 6. Телефон

Список пропусков: на узком экране кнопка «Фильтры» (выезжающая панель `Sheet`) и строка чипов активных фильтров; на широком — как раньше. Форма: обязательное сразу, остальное под «Ещё»; кнопка «Создать пропуск» — `sticky` над нижним меню; поля формы подстраиваются под **ширину своего контейнера** (`@container`), поэтому предпросмотр в узкой колонке редактора не ломается. E2E на 360 px проверяет все страницы кабинета на горизонтальную прокрутку.

## Альтернативы

- **Настройка формы одним JSON на арендатора без уровней**: проще, но «один сотрудник — только фура» и «для всего объекта ФИО скрыты» пришлось бы дублировать по арендаторам.
- **Скрытые поля просто игнорировать на сервере**: тихая подмена значений (CLAUDE.md п. 8); выбрана явная ошибка и предупреждение при загрузке файла.
- **Ограничивать формой и сотрудников оператора**: администратор не смог бы оформить пропуск, который арендатор себе запретил; ограничением остаются права роли.
- **Диспетчер уведомлений отдельным процессом (LISTEN/NOTIFY)**: нужен на этапе 10 для почты и Telegram; для колокольчика транзакционная запись надёжнее и проще для тестов, а контракт каналов уже общий.
- **Библиотека SheetJS/exceljs для .xlsx**: десятки килобайт и спорные версии из npm; для чтения текстовых ячеек хватает zip и XML.
- **Расчёт «сейчас + N ч» в браузере**: часы и пояс браузера ненадёжны (ADR-009); считает сервер.

## Дополнение 7b.1: правки по проверке 7b заказчиком (14.10.2026)

Заказчик проверил 7b и ответил на Q-81–Q-87; этап 7b.1 — правки и дополнения. Решения, которые меняют текст выше:

### 7. Списки без потолка и выгрузка

В PASS24 при любом фильтре видно максимум 60 пропусков — нам так нельзя. `GET /sites/:id/passes` отвечает `{items, total}`: фильтры и поиск — на сервере по **всем** пропускам, список — порциями по 50 (`limit`, `offset`), «Показать ещё» дозагружает следующую порцию, «Найдено N» — `total` по тому же набору условий. Порции в вебе — `useInfiniteQuery` с ключом `data` (события объекта обновляют загруженное без F5), повтор строки на стыке порций отбрасывается по id. Индексы под фильтры — миграция `0013_list_indexes` (`passes`: объект/арендатор × время создания, арендатор × начало; `visits`: открытые визиты по времени въезда).

«Сейчас на территории» — отдельный список (`GET /sites/:id/inside`, `/cabinet/inside`, вкладка «На территории» в карточке арендатора у администратора): все открытые визиты без ограничения, давно въехавшие первыми; время на территории, КПП въезда (название на момент въезда), док и место. Число совпадает с виджетом лимитов: параметр `quotaId` отбирает **те же** визиты, что считает `countOccupancy` (арендатор, типы лимита, без визитов «вне лимита»); клик по виджету «Грузовые 24/25» открывает список с этим лимитом (чип «Лимит: … ✕» снимает его, тогда число = «Сейчас на территории» на главной).

Выгрузка XLSX/CSV — кнопка «Выгрузить» на списке пропусков и на «Сейчас на территории»: **все** строки по текущему фильтру, а не страница (`GET …/passes/export`, `…/inside/export`; тот же набор условий). Право `report.export` + видимость строк как у списка; факт выгрузки — запись аудита `export` (формат, число строк, фильтр без текста поиска). XLSX пишется без тяжёлой библиотеки: zip из нескольких XML (`fflate` 0.8.3, уже в проекте для чтения .xlsx, теперь и в `apps/api` — запись выгрузки), CSV — UTF-8 с BOM, `;`. Время в файле — в поясе объекта, пояс подписан в заголовках колонок. Колонки: номер, тип транспорта, вид пропуска, статус, действует с/по, место назначения, автор, создан, **изменён последним и когда** (последнее событие пропуска в аудите после создания — правка, продление, согласование, отмена; одним запросом `DISTINCT ON` на всю выгрузку, без запроса на строку), на территории сейчас, арендатор. «Выгружаешь только то, что видишь»: нужны `report.export` и право просмотра пропусков (`pass.view` или `pass.view_all_tenants`); без них кнопка неактивна с названием права и ссылкой на роли, сервер отвечает 403 (Q-89).

### 8. Время в форме

- Время вводится только цифрами: `maskTime` / `maskTimeRange` — «1200» → «12:00», «9» → «09», «12001400» → «12:00–14:00»; один компонент `TimeInput` / `TimeRangeInput` для формы, пакета и админки.
- Начало «сейчас» — настройка уровня `startNow` («Время начала — сейчас по поясу объекта, подставлять автоматически», по умолчанию включено): в поле сразу видно текущее время объекта (по часам сервера), пока его не правили; пока не правили, в запрос оно **не уходит** — начало и конец ставит сервер, иначе к моменту «Создать» начало оказалось бы в прошлом.
- Окончание подставляется в поле само как «начало + N часов» и следует за началом, пока его не правили; не позже начала — следующие сутки, видно «завтра» (Q-88).
- Будущая дата без времени — весь день, с 00:00 до 23:59; «начало + 23 ч» только для «с сейчас» (Q-87).

### 9. Окно прибытия

По умолчанию **скрыто** (`PASS_FORM_DEFAULTS.fields.window = 'hidden'`): включают в настройке формы там, где есть расписание доков; под полем подсказка «Узкий интервал, когда машину ждут (например, на док). Пропуск может действовать дольше». Если политика окон требует окно, а форма его скрывает или оно необязательно, сервер ставит окно на весь срок пропуска (Q-81); у постоянного пропуска срока нет, поэтому окно, которого требует политика, остаётся обязательным (Q-91). Пропуск по запросу с поста окно ставит сам — форма «окно скрыто» ему не мешает.

Ошибка окна конкретная — и в сервере (`window_outside_validity`: «Окно 12:00–14:00 начинается раньше начала пропуска (13:50)» / «…заканчивается позже конца пропуска (…)»), и в форме и пакете до запроса, с кнопками-исправлениями одним нажатием: «Начать окно с 13:50», «Закончить окно в …», «Начать пропуск с 12:00» (только если это допустимо по допуску «начало в прошлом», `pastStartToleranceMin`), «Продлить пропуск до …». В пакете исправление меняет окно строки.

### 10. Вид пропуска и док

Если доступно больше одного вида — кнопки-переключатели рядом (`SegmentedChoice`, `role=radiogroup`), «Разовый» выбран сразу; кнопки, которые не помещаются по ширине (телефон 360 px), заменяются обычным списком. **Док обязателен только разовому пропуску** — на сервере (`dock_required`), в подсказках (`dock.required`), форме и пакете, в том числе при «грузовые только к докам»; многоразовый и постоянный — на много поездок, док в каждый приезд свой.

### 11. Продление после въезда (Q-85, Q-90)

Продление «действует до» после въезда — сразу, пока срок не выходит за то, что можно было оформить без согласования (разовый — максимум разового пропуска объекта от начала, многоразовый — максимум дней); сокращение — всегда сразу. **Сверх максимума — всегда через согласование, одинаково для всех** (ответ заказчика 15.10.2026): сервер не отвечает «не дольше N ч», а создаёт заявку на изменение, и предельная длительность при заявке и её одобрении не проверяется (остальные проверки остаются). Если у правящего есть `pass.approve` и `pass.change_request.decide`, заявка создаётся и сразу согласуется им же в той же транзакции (`decideChangeRequest`), причина обязательна; в аудите — `change_request`, `update` пропуска и `approve` заявки, `applied` содержит `validTo`. Без права согласовать форма не отклоняет, а предлагает «Отправить на согласование» (создать такую заявку вправе и тот, у кого есть `pass.edit`); с правом — «Продлить и согласовать». Форма правки показывает до сохранения, до какого момента можно продлить сразу и что произойдёт дальше.

### 12. Редактор формы: несохранённые правки не пропадают (15.10.2026)

Черновик редактора — не копия серверных данных, заполняемая эффектом, а **правки по уровням поверх сохранённого** (`edits`): уровень без правки показывает то, что сохранено, поэтому перезагрузка (после сохранения, по событию объекта) правку не затирает; правка, равная сохранённому, правкой не считается. После сохранения состояние уровня берётся из **ответа сохранения** (`PATCH` отдаёт уровень как он теперь хранится) и кладётся в кэш, а не из последующей перезагрузки. Пока идёт сохранение и перезагрузка, поля, смена сотрудника и уровня заблокированы (CLAUDE.md п. 5) — нажатие не теряется; правки другого уровня сохраняются, об этом сказано под кнопкой. Причина прежнего сбоя: после «Сохранить» эффект по ключу сохранённого заново заполнял черновик пришедшими данными, и «Сбросить к уровню выше», нажатое до прихода перезагрузки, молча затиралось; на быстрой сети окно гонки узкое (тест нестабильный), на медленной — широкое. E2E с искусственно задержанной перезагрузкой (Playwright `route`) падает на прежнем коде стабильно.

### 13. Список пропусков на телефоне (15.10.2026)

На 360 px над списком только строка поиска с кнопкой «Фильтры» и одна строка «Найдено N» вместе с чипами; «Выгрузить» — в панели «Фильтры» (с пояснением, что выгружаются все пропуска по условиям, а не экран), подпись «Поиск» скрыта (остаётся `aria-label`). Порог E2E «первая строка списка выше 380 px» не менялся — запас виден в аннотации теста. Вид пропуска на 360 px: кнопки не помещаются, показывается список (`SegmentedChoice` сам выбирает по ширине).

### Альтернативы 7b.1

- **Загружать списки целиком и фильтровать в браузере** — отвергнуто: у крупного арендатора тысячи пропусков, потолок вернулся бы другим числом.
- **Курсорная пагинация вместо `offset`** — точнее при вставках, но «Найдено N» и E2E «120 из 120» проще на `offset`; повтор на стыке порций отбрасывается по id.
- **Выгрузка на клиенте из загруженных страниц** — отвергнуто: «все строки по фильтру», а не страница.
- **Библиотека xlsx (SheetJS, exceljs)** — не нужна для записи строк; см. ADR-023 п. 4.
- **Ограничить окно «только цифрами» отдельной маской на каждый экран** — отвергнуто: один компонент для формы, пакета и админки.
