# ADR-003. ORM, миграции, RLS и тесты на реальной БД

Статус: принято.

## Контекст

Нужны: транзакции с блокировками (ADR-006), partial- и exclusion-индексы, триггеры `updated_at`, RLS, `LISTEN/NOTIFY`, схема pg-boss. Миграции должны лежать в репозитории и применяться одинаково в CI, в облачной сессии и в проде. Тесты квот и гонок на моках бессмысленны — нужен реальный Postgres.

## Решение

1. **Drizzle ORM 0.45** со схемой в `packages/db/src/schema/*.ts` (один файл на раздел `DATA_MODEL.md`). Типы строк выводятся из схемы; zod-схемы API в `contracts` пишутся отдельно (API ≠ таблица), сверяются тестами типов.
2. **Миграции — SQL-файлы** в `packages/db/migrations/`, генерируются `drizzle-kit generate`, затем **дописываются руками** в том же файле: RLS-политики, exclusion-индексы, триггеры, `check` с `coalesce`, функции. Имя — `NNNN_короткое_описание.sql`. `drizzle-kit push` не используется нигде.
3. Применение — `pnpm db:migrate` (`drizzle-orm/node-postgres/migrator`), таблица `drizzle.__migrations`. Прод: миграции запускаются отдельным шагом перед стартом нового API; все миграции обратно совместимы на один релиз (добавить колонку → задеплоить код → убрать старую в следующей).
4. **Две роли БД:** `oxrana_owner` (миграции, сид) и `oxrana_app` (приложение; без `BYPASSRLS`, без `DELETE`/`UPDATE` на `audit_log`, `domain_events`, `gate_decisions`, `hardware_events`). RLS по `organization_id` — `DATA_MODEL.md` §4.
5. **Raw SQL разрешён** (`sql\`...\``) там, где билдер мешает читать: подсчёт занятости, advisory lock, trigram-поиск, воспроизведение событий. Каждый такой запрос — в `packages/db/src/queries/*.ts` с тестом.
6. **Тесты на реальном Postgres** (Vitest): глобальный setup создаёт шаблонную БД `oxrana_test_template` (миграции + минимальный сид), каждый worker — свою копию `CREATE DATABASE … TEMPLATE …` (≈100 мс), каждый тест — в транзакции с откатом либо `TRUNCATE … CASCADE` для тестов с параллельными соединениями (гонки). Сид Радонежского — отдельная фикстура для сценариев приёмки.
7. **Сид** — `pnpm db:seed` (идемпотентный, по естественным ключам), данные из `docs/reference/лимиты_для_сида.md`, сомнительное помечено `ПРОВЕРИТЬ` в поле `notes`/комментарии.

## Альтернативы

- Prisma, Kysely, TypeORM — см. ADR-001.
- `drizzle-kit push` без файлов миграций: нет истории, нельзя дописать RLS, непригодно для прода.
- Миграции только руками (без генерации): больше ошибок рассинхрона схемы и типов.
- Моки БД / pg-mem: не умеют `FOR UPDATE`, advisory lock, exclusion-индексы — именно то, что мы проверяем.
- Testcontainers: Docker в облачной сессии недоступен (ADR-010).
- RLS по арендатору: у охраны и администратора срез по объекту, а не по арендатору; фильтр по `tenant_id` — в сервисном слое с тест-матрицей.

## Последствия

- Любое изменение схемы = правка `schema/*.ts` + сгенерированная и дополненная миграция + тест. Ревью смотрит SQL, а не только TS.
- Интеграционные тесты требуют запущенного Postgres (`pnpm db:up`); unit-тесты движка и номеров — нет.
