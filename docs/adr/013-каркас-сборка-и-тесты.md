# ADR-013. Каркас: типы, сборка, тесты и окружение

Статус: принято (10.10.2026, этап 1). Дополняет ADR-001, 002, 003, 010; не заменяет их.

## Контекст

Этап 1 «Каркас» превращает решения ADR-001…012 в работающий репозиторий. При этом пришлось выбрать детали, которых в ADR нет: как устроены `tsconfig`, как собирается API из пакетов-исходников, где лежат тесты, какие порты у E2E.

## Решение

1. **Пакеты монорепо — исходники TypeScript.** `exports` пакетов указывают на `src/index.ts`; ни `engine`, ни `contracts`, ни `db` не собираются отдельно. Потребители (Vite, Vitest, tsx) читают TS напрямую.
2. **Типы: `tsc -b` из корня по project references.** Библиотеки (`packages/*`) — `composite`, `emitDeclarationOnly` в `dist/`; приложения и инструменты (`apps/*`, `tsconfig.tools.json` для конфигов, `e2e/`, `scripts/`) — `noEmit`. Все настройки строгости — в `tsconfig.base.json` (`strict`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, `verbatimModuleSyntax`). Чистые пакеты (`engine`, `plates`, `contracts`) без `types: ["node"]` — Node API в них не пройдёт проверку типов.
3. **Сборка API — tsup, workspace-пакеты вшиваются** (`noExternal: [/^@oxrana\//]`), всё прочее остаётся внешним. Внешним считается только то, что объявлено в `dependencies` самого `apps/api`, поэтому `pg` (его использует вшитый `@oxrana/db`) продублирован там — иначе CJS-код драйвера попадает в ESM-бандл и сервер не запускается (поймано дымовой проверкой `scripts/smoke-build.sh`, она же — шаг CI). Для образа в ADR-011 это значит: рантайм-зависимости api = его `dependencies`.
4. **Тесты — два проекта Vitest в корневом `vitest.config.ts`.** `unit` (`*.test.ts` в `{apps,packages}/*/test` и `scripts/`) не требует БД; `integration` (`*.integration.test.ts`) требует `pnpm db:up`, глобальный setup сам применяет миграции. `pnpm test` = оба проекта; `pnpm test:e2e` (Playwright) — отдельно.
5. **Архитектурные проверки — тесты, не только скрипты.** `scripts/check-deps.ts` (ADR-002: слои, `catalog:`, `workspace:*`, нет `node:*` в чистых пакетах) и `scripts/check-no-site-names.ts` (ADR-012 п. 7) вызываются из `scripts/architecture.test.ts` и поэтому идут в `pnpm test:unit` и CI; обе запускаются и как CLI (`pnpm exec tsx scripts/check-deps.ts`). Новый пакет без записи в `WORKSPACE_RULES` ломает тест — слой надо выбрать осознанно.
6. **Конфигурация — переменные окружения, разбор zod** (`apps/api/src/config.ts`): неверное значение — остановка с русским сообщением и именем переменной, никаких молчаливых подстановок. `.env` (в git не входит) создаётся `pnpm db:up` из `.env.example`; процессы читают его через `--env-file-if-exists`.
7. **Порты.** Разработка (`pnpm dev`): API 3000, web 5173, gate 5174. E2E: 3100 / 5273 / 5274 — чтобы не цепляться за чужие процессы. Playwright в сессии берёт Chromium из `/opt/pw-browsers/chromium`, в CI — штатный из `playwright install --with-deps chromium`.
8. **Дерево маршрутов TanStack Router (`routeTree.gen.ts`) коммитится**: `tsc -b` не должен зависеть от предварительной сборки. Генерирует его Vite-плагин при `dev`/`build`; Biome файл не проверяет.
9. **Health:** `/healthz` — процесс жив, БД не трогает; `/readyz` — выполняет `select 1` и при сбое отвечает `503 unavailable`. Оба открыты (`public: true`). Версия — `npm_package_version`.
10. **Логи** — pino с редакцией (`apps/api/src/logger.ts`): заголовки `authorization`/`cookie`, поля `password`, `phone`, `email`, `fullName`, `passport`, `token` на трёх уровнях вложенности заменяются на `[скрыто]`. Модуль, вводящий новое ПДн-поле, дописывает его в `PII_FIELDS`.

## Альтернативы

- **Собирать каждый пакет в `dist` (`tsup --dts`)**: нужен JS-API TypeScript (в 7.0 его нет, ADR-001) и порядок сборки; исходники в экспортах проще и быстрее.
- **Не вшивать workspace-пакеты, запускать API через `tsx` в проде**: тянет компилятор в образ и теряет проверку «что собрано, то и работает».
- **Один проект Vitest с метками**: интеграционные тесты нельзя было бы запускать без БД отдельно (ADR-010 п. 3).
- **Генерировать `routeTree.gen.ts` в `postinstall`**: лишний шаг при каждой установке; коммит файла — рекомендация самого TanStack.

## Последствия

- Любая сессия начинается с `pnpm install && pnpm db:up && pnpm test` (хук делает это сам).
- Тесты прав (ADR-007) на этапе 1 проверяют сам хук на тестовых маршрутах; тест-матрица «маршрут × роль» (`permissions.matrix.ts`) появится на этапе 4 вместе с маршрутами.
- Упаковка образов (ADR-011) обязана учитывать п. 3.
