# ADR-010. База данных для разработки и тестов в облачной сессии

Статус: принято.

## Контекст

Проверка среды (10.10.2026): Ubuntu 24.04, Node 22.22, pnpm 10.28, PostgreSQL 16.15 установлен как системный кластер `16/main` (порт 5432, выключен при старте сессии, `pg_hba`: `peer` локально, `scram-sha-256` по TCP), расширения `pg_trgm`, `pgcrypto`, `btree_gist`, `uuid-ossp` доступны. **Docker CLI есть, демона нет** (`/var/run/docker.sock` отсутствует) — контейнеры и Testcontainers недоступны. Сессия работает от `root`. Контейнер эфемерный: данные БД не переживают сессию.

## Решение

1. **Одна команда поднимает всё:** `pnpm db:up` → `scripts/db-up.sh`:
   ```bash
   service postgresql start                      # кластер 16/main
   su postgres -c "psql -v ON_ERROR_STOP=1" <<'SQL'
   create role oxrana_owner login password 'oxrana' createdb;        -- только для dev/test
   create role oxrana_app   login password 'oxrana';
   create database oxrana        owner oxrana_owner;
   create database oxrana_test_template owner oxrana_owner is_template true;
   SQL
   # идемпотентно: роли/базы создаются, если нет; расширения ставит первая миграция (владелец)
   ```
   `.env.example`: `DATABASE_URL=postgres://oxrana_app:oxrana@127.0.0.1:5432/oxrana`, `DATABASE_ADMIN_URL=postgres://oxrana_owner:…/oxrana`, `TEST_DATABASE_URL=…/oxrana_test_template`.
2. **Миграции и сид:** `pnpm db:migrate` (под `oxrana_owner`), `pnpm db:seed` — демо-объект Радонежский. `pnpm db:reset` = drop + create + migrate + seed.
3. **Тесты** (ADR-003 п. 6): глобальный setup Vitest проверяет доступность `TEST_DATABASE_URL`, мигрирует шаблон, создаёт по базе на worker (`oxrana_test_w<N>`), удаляет после прогона. Unit-тесты `engine`/`plates`/`contracts` БД не требуют и запускаются отдельным проектом Vitest (`pnpm test:unit`), чтобы работать даже без `db:up`.
4. **CI (GitHub Actions):** `services: postgres:16` (там Docker есть) с теми же ролями через init-скрипт; те же команды `pnpm db:migrate && pnpm test`. Один путь для сессии и CI — различается только способ запуска сервера.
5. **Playwright** использует предустановленный Chromium (`PLAYWRIGHT_BROWSERS_PATH=/opt/pw-browsers`), `playwright install` не вызывается; E2E поднимает API + web + gate на свободных портах против `oxrana_e2e` с сидом.
6. **Хук старта сессии** (`.claude/settings.json` → SessionStart): `pnpm install --frozen-lockfile && pnpm db:up && pnpm db:migrate && pnpm db:seed` — чтобы каждая сессия начиналась с рабочей базой. Добавляется на этапе 1.
7. Пароли выше — только для локальной разработки и тестов, в прод не попадают (прод — ADR в этапе деплоя).

## Альтернативы

- **Testcontainers / docker compose**: нет демона в сессии. В CI и у разработчика с Docker они работали бы, но путь должен быть один.
- **Встроенный Postgres через `embedded-postgres` (npm)**: качает бинарники, медленнее, дублирует системный кластер.
- **pg-mem / SQLite для тестов**: не те же гарантии (ADR-003).
- **Общая удалённая dev-БД**: нет сети к ней из сессии и смысла — параллельные сессии мешали бы друг другу.

## Последствия

- `service postgresql start` занимает ~2 с; первая миграция и сид — секунды. Порог входа в сессию — одна команда.
- Если в будущем среда получит Docker, схема не меняется: тот же `db-up.sh` может поднимать контейнер вместо сервиса.
