# ADR-020. Админка: `packages/ui`, карточки и мастер настройки (этап 6a)

Статус: принято (12.10.2026). Реализует `docs/spec/09_админка.md` («Мастер первичной настройки», «Правила качества админки»), ADR-009 (время), ADR-012 (типы и лимиты), ADR-016 (чистый старт).

## Контекст

Заказчик на чистой базе после `bootstrap` сам настраивает объект целиком и проверяет удобство; ориентир — объект уровня Радонежского с нуля за час. Это первые экраны, которые он трогает руками. Нужна общая основа интерфейса (её же потом используют кабинет арендатора и пост), мастер из 11 шагов и те же карточки в меню вне мастера.

## Решение

1. **`packages/ui` — Tailwind 4 и компоненты в стиле shadcn, написанные в репозитории.** Без CLI и реестра shadcn (сеть и версии не под контролем): Button, Card, Field, Input/Select/Checkbox/Switch, Dialog (Radix), Table, Badge, Alert, ChipSelect, SortableList (dnd-kit + кнопки «Выше / Ниже» как запасной путь), Toast. Выпадающий список — родной `<select>` (надёжен на телефоне и с клавиатуры). Темы — переменные CSS, тёмная включается классом `.dark` на `<html>`, выбор помнится в `localStorage` (в `try/catch`). Приложения подключают `@oxrana/ui/styles.css` одной строкой. Внешних шрифтов нет: системный стек работает и без интернета.
2. **Формы (CLAUDE.md п. 5, 8).** `useEditForm`: форма заблокирована и пуста, пока запись не загружена; значений по умолчанию нет; отправляется **только дифф изменённых полей** (PATCH); если менять нечего — запрос не уходит; «Сохранено» появляется только после ответа сервера и держится, пока форма не изменена снова. `useCreateForm` — пустая форма с явно переданными начальными значениями. Проверка до запроса — схемами `@oxrana/contracts`; ошибка сервера `{code, message, field, settingLink}` показывается у поля (если оно есть в форме) или баннером, со ссылкой «Перейти к настройке». Ссылки внутри приложения идут через маршрутизатор (`UiProvider`).
3. **Данные экранов.** TanStack Query, один ключ `['data', путь]`; любое изменение через `useMutate` обновляет все загруженные списки (они маленькие). Взамен ручной инвалидации по каждому справочнику экраны, меню и мастер всегда показывают согласованные данные. Выход очищает кэш.
4. **Пакетный ввод.** Разбор текста — чистые функции в `contracts/batch.ts` (`expandNumberSpec` «1–72», «З1–З7», «А01-А05»; `parsePastedTable` — вставка из Excel; `parseTenantRows`). Предпросмотр «добавится N, ошибки в M» считается локально и мгновенно, а допустимые строки дополнительно проверяет сервер маршрутом с `dryRun`. Новые маршруты: `POST /sites/:siteId/docks/batch`, `POST /sites/:siteId/tenants/batch`, `POST /tenants/:tenantId/dock-assignments/batch` (права `site.manage` / `tenant.manage`, строки в 403-матрице). Строка пакета — вложенная транзакция (SAVEPOINT) тем же кодом, что и одиночное создание (`registerResource(...).create`): аудит и событие по каждой строке, ошибка строки не мешает остальным. Предпросмотр откатывает каждую строку; повторы внутри пакета ловит `precheck`.
5. **Мастер — это карточки, а не копии форм; прогресс считается по данным.** Каждый шаг — компонент-карточка, она же открывается из меню (`/admin/gates`, `/admin/routing`…). Готовность шага (`computeSetupProgress`, чистая функция, юнит-тесты) выводится из данных объекта и нигде не хранится: можно уйти и вернуться, шаг можно пропустить (это просто переход), данные, исправленные в меню, сразу меняют прогресс. Состояния: готово · частично · не начато · ждёт предыдущих · нет данных (нет права читать). Шаг «Проверка» — сводка «что настроено, чего не хватает» со ссылками; прогон вердиктов — этап 6b (песочница).
6. **Меню по правам и неактивное с причиной.** Раздел, на который у пользователя нет права вообще, в меню не показывается («пользователь видит только доступные ему действия»). Раздел, недоступный из-за состояния данных («Сначала создайте объект», «Сначала добавьте КПП и типы транспорта»), показывается неактивным с причиной (CLAUDE.md, «Правила интерфейса»).
7. **Время (ADR-009).** `SiteTimeProvider` задаёт пояс выбранного объекта; `SiteTime` показывает время с подписью пояса («14:32 (Челябинск, UTC+5)»), второй строкой — «у вас …», если включено «моё время». Форматирование — `date-fns` + `@date-fns/tz`; поля формы собираются в мгновение в поясе объекта (`localToInstant`), пояс браузера не читается.
8. **Смена пояса** — отдельная страница `/admin/sites/:id/timezone`: пояс, причина, затем текст последствий от сервера (`confirmation_required`) и явное «Понимаю последствия».
9. **Маршруты (ADR-012 п. 5, RULES_ENGINE §9).** Матрица «тип × КПП» редактирует правила объекта (`tenantId = null`, направление «въезд»); снятая отметка — мягкое удаление правила. Если для типа ничего не отмечено, машина проходит через любой КПП, который её пропускает (так работает движок), — это сказано на экране и учтено в готовности шага.
10. **Тесты.** Новый проект Vitest `components` (jsdom, Testing Library) — входит в `pnpm test:unit`: форма правки (блокировка до загрузки, PATCH только изменённых полей, «Сохранено» после ответа, ошибка у поля со ссылкой), пакетный ввод, диалог удаления. Юнит-тесты `lib/steps.ts` и `contracts/batch.ts`. Интеграционные — пакетные маршруты. E2E на чистой базе: bootstrap → вход → мастер целиком → данные в карточках → PATCH только изменённого → диалог использования КПП → смена пояса.

## Альтернативы

- **shadcn CLI/реестр** — лишняя сетевая зависимость в сессии и на CI; компоненты всё равно копируются в репозиторий.
- **Хранить прогресс мастера в БД** — расходится с реальными данными, как только их правят вне мастера; прогресс «по данным» всегда правдив.
- **Отдельные формы для мастера и для меню** — дублирование и расхождение; поэтому шаг = карточка.
- **Radix Select / Combobox** — красивее, но хуже на телефоне и в тестах; родной `<select>` достаточен.
- **Серверный маршрут «готовность объекта»** — лишний API при уже существующих списках; расчёт на клиенте проверяется юнит-тестами.

## Последствия

- В `package.json` приложений — новые зависимости (через `catalog:`): Tailwind 4, Radix Dialog, class-variance-authority, clsx, tailwind-merge, lucide-react, TanStack Query, react-hook-form, @hookform/resolvers, date-fns, @date-fns/tz, dnd-kit; для тестов — Testing Library, jsdom 29 (требует Node ≥ 22.13).
- Типы транспорта из набора не удаляются, а выключаются: уникальный индекс `vehicle_categories_preset_key` не исключает мягко удалённые строки, и повторное включение удалённого типа дало бы конфликт.
- Маршруты арендатора (`routing_rules.tenant_id` — приоритетнее общей матрицы; в карточке показано только их число), редактор ролей, загрузка PDF договора, блокировка арендатора — этап 6b.
- В сообщениях форм, где схемы `contracts` дают английский текст zod, экраны расширяют схему русскими сообщениями (русская локаль zod в `contracts` не подключена) — кандидат на общую настройку.
