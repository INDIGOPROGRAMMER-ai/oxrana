# ADR-006. Гарантия лимита при одновременном въезде

Статус: принято.

## Контекст

Сценарий 37: грузовые ДНС 24/25; в один момент малотоннажный на КПП-1 и фура на КПП-2, оба охранника нажимают «Впустить». Впустить надо ровно одну. Лимит считается по открытым визитам (CLAUDE.md п. 3), проверка и запись — одна транзакция с блокировкой (`16_` B4). Два API-инстанса не должны ломать гарантию.

## Решение

Въезд выполняется функцией `checkIn()` в одной транзакции `READ COMMITTED`:

```sql
begin;
set local app.organization_id = :org;                     -- RLS
select pg_advisory_xact_lock(hashtext('tenant:' || :tenant_id));   -- 1. одна блокировка на арендатора
-- 2. свежая занятость по всем лимитам арендатора (после получения блокировки!)
select q.id, count(v.id) filter (where v.time_out is null and not v.waives_quota) as occupied
  from quotas q left join visits v on v.tenant_id = q.tenant_id and v.category_id = any(group_category_ids(q.id))
 where q.tenant_id = :tenant_id and q.deleted_at is null and q.valid... group by q.id;
-- 3. движок: evaluate({..., state: {occupancy}})
-- 4. если verdict ∈ (allow, allow_overage) или override:
insert into visits (...) values (...);
insert into gate_decisions (...);                          -- с trace
insert into domain_events (type 'visit.opened'), (type 'quota.changed');
insert into audit_log (...);
-- иначе: только gate_decisions + domain_events ('gate_decision.wait'), визита нет
commit;                                                    -- блокировка снимается
```

- Ключ блокировки — **арендатор**, а не лимит: тип транспорта может входить в несколько лимитов (A2), одна блокировка исключает порядок захвата и дедлоки. Конкуренция реальна только между машинами одного арендатора на двух-трёх КПП — ожидание единицы миллисекунд.
- `hashtext()` даёт `int4`; коллизия двух арендаторов лишь слегка сериализует их — корректность не страдает.
- Занятость читается **после** получения блокировки, поэтому вторая транзакция видит визит первой, даже при `READ COMMITTED` (каждый statement видит закоммиченное на момент своего старта).
- Partial-индекс `visits (site_id, tenant_id, category_id) where time_out is null` делает подсчёт константным по времени — у арендатора открыто десятки визитов, не тысячи.
- `check_out` блокировку не берёт: он только освобождает место; после коммита `queue.slot_freed` отправляется первому в `gate_queue`.
- `undo` въезда — та же блокировка (закрывает визит с флагом `undone`, занятость уменьшается).
- Офлайн-синхронизация (ADR-005) идёт через ту же функцию с режимом `acceptOverQuota = true`.
- Тест: два соединения, `pg_sleep`-инъекция между чтением и записью через `app.test_delay`, ожидаем ровно один визит и один `wait`. Отдельный тест — 20 параллельных въездов при capacity 5 → ровно 5 визитов.

## Альтернативы

- **Таблица счётчиков `quota_counters` + `SELECT … FOR UPDATE`**: нужно поддерживать счётчик при каждом въезде/выезде/undo/синхронизации и ночная сверка (`10_` §1 это допускает). Подсчёт по индексу обходится без второго источника правды. Вернёмся к счётчикам, если `count` станет дорогим (не раньше тысяч открытых визитов на арендатора).
- **`SERIALIZABLE`**: корректно, но даёт ошибки сериализации под нагрузкой и требует повторов во всех вызывающих местах; advisory lock проще объяснить и проверить.
- **Блокировка строки `tenants` через `FOR UPDATE`**: работает, но мешает параллельному редактированию карточки арендатора и не выражает намерения; advisory lock — именно «логическая очередь на въезд».
- **Блокировка в приложении (mutex)**: не работает при двух инстансах API.
- **Проверка лимита до транзакции, запись — после**: ровно та гонка, которую запрещает ТЗ.

## Последствия

- Вердикт на экране поста (из `POST /gates/{id}/check`) — предварительный; окончательный — внутри `checkIn`. Если между ними место заняли, пост получает `wait` в ответ на «Впустить» и показывает его без перезагрузки (сценарий 37).
- Все пути создания визита (кнопка, QR, камера, автопроезд, синхронизация) обязаны идти через `checkIn()`; прямых `insert into visits` в коде нет (линт-правило на импорт таблицы вне `packages/db/src/queries/visits.ts`).
