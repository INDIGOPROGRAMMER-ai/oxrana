# ADR-012. Типы транспорта и лимиты без «групп»

Статус: принято (10.10.2026). Исправляет `DATA_MODEL.md` (убраны `category_groups`), `RULES_ENGINE.md` §1 и §4, `04_доменная_модель.md` (CategoryGroup).

## Контекст

Решение заказчика:
- справочник типов транспорта с готовым рекомендованным набором; администратор включает нужные одним кликом, может добавить свой тип и переименовать любой; порядок в списках задаётся перетаскиванием; тип при выборе не подставляется молча;
- спецтехника — обычный тип со своим лимитом;
- лимит ставится на один тип или на несколько типов вместе («Грузовые» = малотоннажный + фура + грузовой свыше 5 т); в интерфейсе — «[выбрать типы] — [число]», никаких отдельных «групп» пользователь не создаёт;
- КПП полностью настраиваемые: сколько угодно, «кого пропускает» (машины и пешеходы / только машины / только пешеходы), для машин — матрица типов, вид поста (периметр / внутри здания). Про Радонежский в коде — ничего.

## Решение

1. **Справочник типов** (`vehicle_categories`): у организации, с переопределением на объекте. Поля: `preset_code` (ключ из рекомендованного списка или `null` для своего), `name` (переименовывается свободно), `enabled`, `sort` (перетаскивание), `dock_eligible` («обычно едет к доку» — для настройки «грузовые только к докам»). Рекомендованный список — константа `VEHICLE_CATEGORY_PRESETS` в `packages/contracts`: `car` легковой, `light_truck` малотоннажный, `semi` фура, `truck_5t` грузовой свыше 5 т, `special` спецтехника, `bus` автобус, `moto` мототехника, `trailer` прицеп, `minibus` микроавтобус. Мастер показывает список с галочками; выключенный тип не виден в формах, но остаётся в истории.
2. **Группы типов убраны из модели.** Лимит (`quotas`) связан с типами напрямую через `quota_categories (quota_id, category_id)`. Один тип может входить в несколько лимитов — тогда действуют все, вердикт по самому строгому (прежняя семантика A2 сохранена). Лимит на пешеходов — `participant = 'pedestrian'` без типов. Имя лимита (`quotas.name`) заполняется автоматически из названий типов («Малотоннажный + фура + грузовой свыше 5 т») и редактируется («Грузовые») — это подпись на табло и в кабинете.
3. **Политики окна прибытия** тоже ссылаются на типы напрямую: `time_window_policy_categories`. Настройка арендатора «грузовые только к докам» применяется к типам с `dock_eligible`.
4. **Форма лимита** в карточке арендатора: строка «Лимит: [мультивыбор типов] — [число] · режим [жёсткий / мягкий / информирующий] · основание [пункт договора]». Подсказка под строкой: «Этот тип уже входит в лимит „Грузовые“ — будут действовать оба». Кнопка «Как у договора» в мастере предлагает типовые наборы: «Легковые» = {car}, «Грузовые» = {light_truck, semi, truck_5t}, «Спецтехника» = {special}.
5. **КПП** (`gates`): `admits ∈ {vehicles_and_pedestrians, vehicles, pedestrians}`, `kind ∈ {perimeter, internal}`, матрица «тип × КПП» — `routing_rules`. Движок перед маршрутом проверяет `gate_admits`: пешеход на КПП «только машины» → `wrong_gate` без каких-либо правил маршрута; пешеход на КПП, который пешеходов пропускает, — проходит (если нет правил арендатора с другим указанием).
6. **Никаких дефолтов типа** в формах создания, кроме явно заданного арендатором `default_category_id` («фура» для X5) — и он показывается как предзаполненное поле, а не подставляется при сохранении.
7. Сид Радонежского — обычные данные справочника: пять включённых типов, три лимита-набора, три КПП (`КПП офис`: `internal`, `pedestrians`). В коде приложения ни одно название объекта не встречается; это проверяется grep-тестом в CI (`scripts/check-no-site-names.ts` ищет «Радонеж», «ДНС», «КПП-1» вне `packages/db/seed` и `docs`).

## Альтернативы

- **Оставить `category_groups` как скрытую сущность, создаваемую автоматически**: лишний слой и лишние миграции ради таблицы, которую никто не видит; прямые связи проще в запросах и в движке.
- **Массив `category_ids uuid[]` в `quotas`**: короче, но без FK — удаление типа не проверяется базой. Таблица-связка сохраняет целостность и подсчёт «используется в N лимитах» при мягком удалении.
- **Фиксированный `enum` типов в коде**: заказчик требует свои типы и переименование.

## Последствия

- `RuleSet.groups` исчезает; `quotas[].categoryIds` и `gates[].admits` появляются. Сценарии 4, 5, 11, 12, 33 не меняются по смыслу.
- UI-термины: «Тип транспорта» и «Лимит» (Q-42 закрыт 10.10.2026, вариант «а»); в коде остаются `vehicle_category` и `quota`. В ТЗ (`docs/spec/`, `docs/reference/`) прежние слова «категория» и «квота» не правились.
