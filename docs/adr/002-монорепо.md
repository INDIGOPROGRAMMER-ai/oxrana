# ADR-002. Структура монорепо

Статус: принято.

## Контекст

Четыре приложения с разными режимами работы (API, веб-кабинет с админкой, киоск поста, агент КПП) и общий код (движок, схемы, номера, контракты оборудования). Разработка в коротких облачных сессиях с холодным кэшем: каждая сессия — свежий контейнер.

## Решение

```
oxrana/
├─ apps/
│  ├─ api/          Fastify: REST, SSE, задачи pg-boss, адаптер почты/SMS/Telegram
│  ├─ web/          React SPA: админка + кабинет арендатора + публичная страница водителя (/p/:token)
│  ├─ gate/         PWA поста охраны (киоск, офлайн). Отдельное приложение: свой service worker, свой UI-масштаб
│  └─ gate-agent/   Агент КПП (Node): адаптеры камер/реле, симуляторы. Этап «оборудование»; в MVP — симуляторы для E2E
├─ packages/
│  ├─ engine/       Движок вердикта. Чистый, без зависимостей
│  ├─ plates/       Нормализация и форматы номеров, нечёткое совпадение. Чистый
│  ├─ contracts/    zod-схемы API и событий, коды ошибок, коды прав, типы настроек, тексты ошибок. Без runtime-зависимостей кроме zod
│  ├─ hardware/     Контракты событий/команд оборудования, интерфейсы адаптеров, симуляторы
│  ├─ db/           Drizzle-схема, миграции, сид «ЛЦ Радонежский», хелперы RLS, тестовый harness БД
│  └─ ui/           Общие компоненты shadcn и токены темы для web и gate (появляется на этапе поста)
├─ docs/            ТЗ, архитектура, ADR
├─ scripts/         db-up.sh (ADR-010), seed, проверка версий
├─ .github/workflows/ci.yml
├─ pnpm-workspace.yaml   (+ catalog общих версий)
├─ package.json          корневые скрипты: dev, build, typecheck, lint, test, test:e2e, db:*
├─ tsconfig.base.json    strict-настройки; каждый пакет — tsconfig с references
└─ biome.json
```

Правила:
- Зависимости между пакетами — только `workspace:*` и только «вниз»: `apps/* → packages/*`, `packages/db → contracts`, `engine → (ничего)`, `plates → (ничего)`, `contracts → zod`. Проверяется тестом на граф импортов (`scripts/check-deps.ts`).
- Публичная страница водителя живёт в `apps/web` как неавторизованный маршрут: отдельный деплой не нужен, бандл делится по маршрутам.
- Киоск поста — отдельное приложение, а не маршрут `web`: другой масштаб UI (кнопки 64 px, тёмная тема), агрессивный офлайн-кэш, автозапуск; не должно подтягивать код админки.
- Общие версии зависимостей (react, zod, typescript, vitest) — в `pnpm-workspace.yaml` → `catalog:`; расхождения версий между пакетами запрещены (`pnpm dedupe --check` в CI).
- Скрипты запускаются рекурсивно: `pnpm -r --parallel dev`, `pnpm -r typecheck`, `pnpm -r test`. Typecheck — `tsc -b` по project references из корня.

## Альтернативы

- **Turborepo 2.11 / Nx**: кэш задач бесполезен в эфемерных контейнерах, а удалённый кэш — ещё один сервис. Pipeline-зависимости («сначала собрать `contracts`») решаются `tsc -b` и `pnpm -r` с топологическим порядком. Отказ экономит зависимость; вернуться можно за час.
- **Несколько репозиториев**: отвергнуто — движок и контракты должны меняться атомарно с API и постом.
- **Один SPA на всё** (пост внутри `web`): отвергнуто, см. выше.
- **Страница водителя отдельным приложением**: лишний деплой ради одной страницы.

## Последствия

- Любая сессия Claude Code начинает с `pnpm install && pnpm db:up && pnpm test` — меньше трёх минут.
- Добавление приложения = папка в `apps/` + запись в workspace; никаких конфигов оркестратора.
