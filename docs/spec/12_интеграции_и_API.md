# Интеграции и API

## API платформы [MVP]

REST + JSON, документация OpenAPI. Свои клиенты (веб, PWA, бот) работают через тот же API — «API-first».

Ключевые эндпоинты:
- `POST /passes`, `POST /passes:batch` — одиночное и пакетное создание; пакетный ответ построчный: `created` / `errors[]`.
- `PATCH /passes/{id}` — только изменённые поля, обязательный `reason` для начавшихся пропусков.
- `POST /gates/{id}/check` — вердикт по номеру или пропуску: `{verdict, reasons[], quota_states[], suggested_gate}`.
- `POST /gates/{id}/check-in`, `/check-out`, `/refuse`, `/override`.
- `POST /gate-requests` — «машина без пропуска»; ответ арендатора — `POST /gate-requests/{id}:approve`.
- `GET /sites/{id}/occupancy` — заполненность квот (для табло и кабинета).
- `GET /reports/...` — выгрузки XLSX/CSV синхронно (для больших — фоновая задача со ссылкой в интерфейсе, а не на почте на 24 часа).

Реальное время: WebSocket или SSE-канал объекта с событиями `visit.created`, `visit.closed`, `pass.created`, `quota.changed`, `gate_request.*`. Пост охраны и кабинет обновляются без F5.

Ошибки — структурированные: `{code, message, field, setting_link}`. Пример: `pass_type_forbidden: «Политика „Охрана → Временный“ = Запрещено. Изменить: Настройки → Политики создания»`.

## Вебхуки [v2]

События для внешних систем арендатора и оператора: въезд и выезд, отказ, сверхлимит, нарушение, согласование. Подпись HMAC, повторы.

## Уведомления [MVP]

- E-mail (транзакционный SMTP-провайдер).
- Push в PWA (Web Push).
- Telegram-бот: уведомления арендатору и быстрые ответы «Оформить / Отклонить» на запросы с поста. [v2 — заказ пропусков в боте]
- SMS — только для приглашений и кодов входа (провайдер РФ).

## Оборудование [v3]

- **Камеры распознавания номеров (ANPR/LPR).** Камера на въезде отправляет номер → система открывает карточку на посту и выносит вердикт. Охраннику остаётся подтвердить, а при зелёном и включённой автоматике проезд открывается сам. Нужен адаптер под конкретные камеры и ПО; в вендорской базе PASS24 есть статьи про PASS24.auto и типичные проблемы распознавания.
- **Шлагбаумы и ворота.** Реле или контроллер (Wi-Fi/GSM-реле, контроллеры СКУД); «Впустить» = открыть.
- **СКУД** (Sigur, Perco, Болид) — синхронизация пешеходных пропусков и карт.
- **QR-сканеры:** USB-сканер на посту или камера планшета.

## Учёт и деньги [v2]

- Выгрузка сверхлимитов и штрафов в 1С (XLSX/CSV по шаблону или обмен через HTTP-сервис 1С).
- Отчёт по форме приложения 4 договора ДЛ-Транса.

## Импорт из PASS24 [MVP, для миграции]

PASS24 даёт выгрузки:
- «Отчёты → Экспорт данных» (пропуска, адреса, пользователи) — письмом на почту, ссылка живёт 24 часа;
- «Экспорт событий пропусков» (облако на экране «Пропуска») — до 31 дня.

План:
1. Выгрузить адреса, пользователей и пропуска.
2. Сопоставить:
   - адреса «(Арендатор легковые/грузовые)» → один арендатор;
   - тип транспорта PASS24 → категория;
   - тип пропуска → `pass_type`.
3. Перенести только действующие постоянные и многоразовые пропуска.
4. История — архивной таблицей, без пересчёта квот.
5. Пользователей арендаторов пригласить заново.

У PASS24 есть публичный API базы знаний (FastAPI, видно по ошибкам). Официальный API для данных стенда не подтверждён — спросить вендора (вопрос 25 в §25 базы).
