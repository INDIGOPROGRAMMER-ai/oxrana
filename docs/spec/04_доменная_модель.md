# Доменная модель

## Ключевая идея

В PASS24 одна сущность «адрес» отвечает сразу за три вещи: куда едет машина, сколько машин можно и (через КПП) где их пускать. Мы разводим это на независимые правила:

```
           ┌──────────── КУДА ─────────────┐
Арендатор ─┤  Помещения · Доки · Зоны парковки
           │
           ├──────────── СКОЛЬКО ──────────┐
           │  Квоты: группа категорий × зона × лимит × режим
           │
           └──────────── КАК ВПУСКАЕМ ─────┐
              Маршруты: категория/участник → разрешённые КПП
              Окна времени · Исключения · Согласования
```

Охранник получает **вердикт**: результат проверки всех правил для конкретного пропуска на конкретном КПП в конкретный момент.

## Сущности

### Организация и объект
- **Organization** — оператор (ООО «Интеграция»). Мультиарендность SaaS: всё ниже принадлежит организации.
- **Site** (объект) — ЛЦ «Радонежский».
  - Параметры: адрес, координаты, часовой пояс (`Asia/Yekaterinburg`), рабочее время комплекса, контакты.
  - Настройки по умолчанию: допуски окон, сроки пропусков, хранение.
- **Building / Zone** — здания и зоны территории: «основной склад», «стр. 5», «АБК», «парковка у столовой», «зона у доков юг».
- **Gate** (КПП) — точка въезда/выезда.
  - Поля: название, направление (въезд / выезд / оба), режим работы, устройства.
  - Правила маршрута лежат отдельно — см. **RoutingRule**.
- **Dock** — пронумерованный док. Поля: номер, здание, зона, тип (с доклевеллером / наземные ворота), ворота-размеры, текущий арендатор (через назначение со сроком действия).
- **ParkingArea** — участок для стоянки: количество мест (если известно), разметка, кому выделен.

### Справочники
- **VehicleCategory** — легковой · малотоннажный · грузовой от 10 т · фура · спецтехника · автобус служебный · мототехника… Справочник на уровне организации с переопределением на объекте.
  - Атрибуты: код, название, «группа по умолчанию» (легковые / грузовые), нужен ли док, порядок.
- **CategoryGroup** — группа категорий для квот: «Легковые» = {легковой}; «Грузовые» = {малотоннажный, грузовой от 10 т, фура, спецтехника}.
  - Группа может быть своя у арендатора. Пример — Континент: «Грузовые до 4,5 т» = {малотоннажный}.
- **ParticipantType** — `vehicle` | `pedestrian`. Пешеход — это не «машина без типа».
- **VisitPurpose** — цель визита: разгрузка, погрузка, доставка, гость, сотрудник, подрядчик… У цели может быть норматив времени на территории (аналог «Минут» в PASS24).
- **PlateFormat** — форматы номеров по странам (RU, BY, KZ, UZ, TJ, KG, AM…) и нормализация.

### Арендатор и договор
- **Tenant** — компания-арендатор: ИНН, название, короткое имя для экранов охраны, статус (активен / заблокирован / в архиве), цвет и иконка.
- **Contract** — договор арендатора: номер, дата, стороны, срок, PDF, статус.
  - **ContractClause** — выписанные пункты: «п. 2.1 — 30 легковых мест», «прил. 2 — доки №1–18…».
  - На пункт ссылаются квоты, исключения и назначения доков.
- **TenantAssignment** — что закреплено за арендатором: помещения, доки, места в ParkingArea. Со сроками `valid_from` / `valid_to`, чтобы история не переписывалась.
- **TenantUser** — люди арендатора: логист, диспетчер, ответственный.
  - Роль внутри арендатора.
  - Приглашение по SMS или e-mail.
  - Может работать у нескольких арендаторов.
- **Fleet** — постоянный автопарк арендатора: номер, категория, марка, водитель по умолчанию. Шаблоны для быстрого заказа.

### Правила
- **Quota** — «сколько одновременно».
  - **Поля:**
    - `tenant`, `site`, `category_group` (или участник `pedestrian`);
    - `zone` / `docks` (необязательно — для ссылки и отчёта);
    - `capacity` (число; для доков — можно вычислять как количество назначенных доков);
    - `counting`: `on_site` (на территории сейчас) | `active_passes` | `per_day` (заездов за сутки);
    - `enforcement`: `hard` (не пускать) | `soft` (пускать сверх с начислением) | `warn` (только предупреждение);
    - `overage_tariff` (₽/сутки за единицу сверх), `overage_cap` (максимум сверх, если есть);
    - `schedule` (если квота действует только в определённые часы);
    - `basis_clause` → ContractClause;
    - `valid_from` / `valid_to`.
  - **Примеры:**
    - ДНС: «Грузовые», 25, on_site, hard, основание прил. 2. ДНС: «Легковые», 30, on_site, hard, п. 2.1.
    - ДЛ-Транс: «Легковые», 15, on_site, soft, 67 ₽/сутки, п. 1.1 и п. 3.1.1. ДЛ-Транс: «Грузовые», 7, soft, 233 ₽/сутки.
    - Континент: «Грузовые до 4,5 т» = {малотоннажный}, 22, hard. Фуры Континента — квота 0 → «не предусмотрено договором».
    - Мастервент: «Грузовые», 0, hard.
- **RoutingRule** — «через какой КПП».
  - Поля: `site`, (`participant_type`, `category`) → разрешённые `gates[]`, приоритет, расписание.
  - Пример: малотоннажный → КПП-1; фура → КПП-2; пешеход → КПП-1.
  - Можно переопределить для арендатора (например, X5 всегда через КПП-2).
- **TimeWindowPolicy** — окна времени для пропусков.
  - Применяется к сайту, арендатору, категории.
  - Поля: обязательность окна (для грузовых — да), допуск раньше (`early_tolerance_min`, например 0 или 15), допуск позже (`late_tolerance_min`, либо «до конца пропуска»), поведение при нарушении (hard / warn).
- **Exception** — исключение из проверок с явной областью:
  - «служебный автобус ДНС: без досмотра, вне квоты легковых»;
  - «X5: окна времени не применяются, 24/7»;
  - «руководство ЛЦ: все КПП, вне квот».
  
  Поля: основание, срок, кто создал.
- **ApprovalPolicy** — кто и что согласует.
  - Пример: «разовый — авто-одобрение; временный и постоянный — директор ЛЦ; комментарий обязателен».
  - Может быть условной: доверенный арендатор, повторяющийся номер из автопарка — авто.
- **Blacklist** — номера и люди: уровень объекта или организации, причина, срок.

### Пропуск и визит
- **Pass** — разрешение на въезд.
  - **Тип:** `single` (один въезд-выезд) | `multi` (много въездов в интервале) | `permanent`.
  - **Участник:** машина (номер нормализованный + исходный, страна, категория, марка — необязательно, водитель — необязательно) или пешеход (ФИО, документ — необязательно).
  - **Связи:** `tenant`, `destination` (помещение / док / зона — необязательно), `purpose`.
  - **Время:** `valid_from` / `valid_to` и/или `time_window` (окно прибытия для грузовых).
  - **Статус пропуска:** `draft` → `pending_approval` → `approved` (активен) | `rejected` | `cancelled` | `expired` | `used` (для single после выезда).
  - **Прочее:** создатель, канал (веб, PWA, бот, API, охрана), комментарий, пакет-источник (`batch_id`).
  - Редактирование — через PATCH, всё пишется в журнал.
- **Visit** — фактическое пребывание.
  - Поля: `pass`, `gate_in`, `time_in`, `guard_in`, `gate_out`, `time_out`, `guard_out`, метод (кнопка, QR, камера номеров).
  - **Снимок на момент въезда:** арендатор, категория, номер, квоты.
  - Флаги: `overage` (въезд сверх мягкой квоты), `exception_id`, нарушения.
  - **Квоты считаются по открытым Visit, а не по Pass.**
- **GateDecision** — каждая проверка на КПП.
  - Поля: время, КПП, пропуск или номер, вердикт (`allow` / `wait` / `deny` / `wrong_gate` / `no_pass`), причины, кто и что нажал, переопределение с причиной.
  - Это журнал отказов и попыток, которого в PASS24 нет совсем.
- **GateRequest** — «машина на воротах без пропуска»: запрос арендатору или админу, ответ, созданный пропуск.

### Нарушения и деньги
- **Violation** — нарушение Правил комплекса.
  - Поля: тип (парковка вне мест, скорость, курение, ремонт…), арендатор, визит, фото, автор, статус акта (черновик → подписан → оспорен), штраф (5 000 ₽ по Правилам), пункт Правил.
- **OverageCharge** — начисление за сверхлимит: арендатор, квота, визит, сутки, тариф, сумма, период отчёта (форма прил. 4 ДЛ-Транса).

### Люди и устройства
- **Staff** — сотрудники оператора: администраторы, согласующие, охранники (ФИО, телефон, роль).
- **GateDevice** — устройство поста: компьютер или планшет КПП, привязан к Gate. Долгоживущий токен, отзыв, последний онлайн.
- **Shift** — смена охранника на устройстве: вход по PIN, время, передача смены с комментарием.
- **AuditLog** — все изменения сущностей: было → стало, кто, когда, откуда.

## Вердикт на КПП: порядок проверки

Для пропуска P на КПП G в момент t:
1. **Пропуск найден и активен?** Если нет — `no_pass`; проверить заявки и предложить `GateRequest`.
2. **Чёрный список?** Да — `deny` с причиной.
3. **Арендатор и пользователь не заблокированы?** Заблокированы — `deny`.
4. **Маршрут.** Входит ли G в разрешённые КПП для (участник, категория, арендатор)? Нет — `wrong_gate`: «направьте на КПП-2».
5. **Окно времени.** `t ≥ начало − допуск`? Если раньше — `wait`: «рано, въезд с 14:00 (через 25 мин)». Позже конца + допуск — `deny` или `warn` по политике.
6. **Квота.** Для каждой квоты, куда попадает категория пропуска, `occupied + 1 ≤ capacity`?
   - hard — `wait`: «ДНС грузовые 25/25 — ждать выезда»;
   - soft — `allow` с флагом `overage` и строкой «сверх лимита, начисление 233 ₽/сутки»;
   - warn — `allow` с предупреждением.
7. **Исключения** могут снять шаги 4–6 (например, автобус ДНС, X5 24/7).
8. **Итог** — `allow` и большая зелёная кнопка «Впустить».

Выезд: открытый Visit найден → «Выпустить». Если не найден, сценарий «выезд без отметки въезда»: причина, уведомление.

`wait`, `deny` и `wrong_gate` блокируют основную кнопку. Переопределить их можно только правом `gate.override` с обязательной причиной; это попадает в журнал и уведомление админу.

## Как это закрывает обходные пути PASS24

| Было в PASS24 | Стало |
|---|---|
| 2 адреса на арендатора ради двух лимитов | 1 арендатор, 2 квоты (Легковые, Грузовые) |
| Малотоннажные: квота грузовых, но КПП-1 — конфликт адреса и фильтра КПП | Квота «Грузовые» включает малотоннажный; маршрут: малотоннажный → КПП-1 |
| Пешеходы не видны на КПП с типами | Пешеход — участник, маршрут «пешеход → КПП-1» |
| «Пропуска нет» вместо «не тот КПП» | Вердикт `wrong_gate` с подсказкой |
| Лимит активных пропусков на пользователя | Квота на арендатора по присутствию |
| ДЛ-Транс сверх лимита за доплату — невозможно | Мягкая квота с тарифом и отчётом |
| Переименование адреса переписывает историю | Снимки в Visit / GateDecision, назначения со сроками |
