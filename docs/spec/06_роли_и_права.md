# Роли и права

Принципы:
- Права даются на **действия**, а не на экраны.
- Новая роль создаётся **без прав**.
- Права ограничиваются областью: организация / объект / КПП / арендатор.
- «Отмечать въезд и выезд» и «редактировать пропуск» — разные права. Именно этого не хватало в PASS24.

## Права (атомарные)

| Код | Что разрешает |
|---|---|
| `site.manage` | Настройки объекта, КПП, зон, доков, маршрутов |
| `tenant.manage` | Арендаторы, договоры, назначения |
| `quota.manage` | Квоты, исключения, окна времени |
| `user.manage` | Сотрудники оператора, роли |
| `tenant_user.manage` | Пользователи арендатора (для админа — любые; для ответственного арендатора — свои) |
| `pass.create.single` / `.multi` / `.permanent` | Создание пропусков по типам |
| `pass.create_for_any_tenant` | Создавать за любого арендатора (админ, охрана в режиме «без пропуска») |
| `pass.edit` | Менять содержимое пропуска (номер, категорию, время) с причиной |
| `pass.cancel` | Закрыть или отменить пропуск |
| `pass.approve` | Согласовывать по политике (директор ЛЦ) |
| `visit.check_in` / `visit.check_out` | Впустить / выпустить |
| `gate.override` | Переопределить вердикт `wait` / `deny` / `wrong_gate` с причиной |
| `gate.request` | Создать запрос «машина без пропуска» |
| `violation.create` / `violation.manage` | Фиксировать нарушение / вести акты |
| `report.view` / `report.export` | Отчёты |
| `audit.view` | Журнал аудита |
| `device.manage` | Привязка устройств КПП |

## Шаблоны ролей

| Роль | Область | Права |
|---|---|---|
| Владелец организации | организация | всё |
| Администратор объекта | объект | всё, кроме биллинга платформы |
| Согласующий (директор ЛЦ) | объект | `pass.approve`, `report.view`, просмотр всего |
| Охранник | КПП (через устройство) | `visit.check_in/out`, `gate.request`, `violation.create`; **без** `pass.edit` и `gate.override` |
| Старший смены | объект | охранник + `gate.override`, `pass.edit` (только номер и комментарий) |
| Бухгалтер | организация | `report.view/export` по начислениям и нарушениям |
| Арендатор — ответственный | свой арендатор | создание пропусков по политике, `tenant_user.manage` своих, отчёты по себе |
| Арендатор — заказчик | свой арендатор | создание пропусков, свои пропуска |
| Арендатор — наблюдатель | свой арендатор | только просмотр |

## Политика создания пропусков

Режим на объекте, по роли и типу пропуска: `allow` / `on_request` / `deny`. Это хорошая идея PASS24, сохраняем.

Пример для Радонежского:

| | Разовый | Временный | Постоянный |
|---|---|---|---|
| Арендатор | allow | on_request (директор) | on_request (директор) |
| Охрана | on_request («без пропуска» → арендатор или админ) | deny | deny |
| Админ | allow | allow | allow |

Ошибка «запрещено» всегда называет, **какая** политика сработала и где её поменять.
