# Бизнес-правила и крайние случаи

## 1. Подсчёт квот

- **Занятость** квоты Q:
  - считается число открытых визитов (въезд без выезда) арендатора Q.tenant, у которых категория входит в Q.category_group;
  - визиты по исключению с флагом «вне квоты» не считаются;
  - на хранении или в кэше — счётчик, пересчитываемый по событиям, плюс ночная сверка.
- **Одна машина попадает в несколько квот** (например, «Грузовые» и «Грузовые у дока юг») → проверяются все, вердикт по самой строгой.
- **Заказанные пропуска квоту не занимают.** Можно включить режим `active_passes` для объектов, где хотят считать по пропускам; режим `per_day` — для лимита «заездов в сутки».
- **Мягкая квота:**
  - въезд сверх лимита разрешён, визит помечается `overage`;
  - начисление = количество суток (календарных по местному времени, неполные считаются полными — как в договоре ДЛ-Транса) × тариф;
  - если сверх нескольких машин, сверхлимитными считаются последние въехавшие в моменте.
- **Квота 0** = категория не предусмотрена. Вердикт красный: «грузовые не предусмотрены договором».
- **Квота «по докам»** может быть вычисляемой (= число назначенных доков) или заданной вручную. Пример: у ДНС 25 доков с доклевеллерами и 11 наземных ворот; в квоту идут только 25.
- **Смена квоты посреди дня** не выгоняет тех, кто внутри. Новые въезды проверяются по новой квоте.

## 2. Маршрут

- Разрешённые КПП = правило по (участник, категория), а также переопределение для арендатора, если есть.
- Выезд разрешён через любой КПП, если не задано иначе. Сценарий «въехал на КПП-1, выезжает через КПП-2» должен работать.
- Пешеход: отдельный маршрут (Радонежский — только КПП-1).

## 3. Время

- Всё хранится в UTC и показывается в поясе объекта.
- **Разовый пропуск:**
  - длительность от 1 до N часов (на Радонежском N = 24);
  - после выезда — статус `used`;
  - повторный въезд — только по новому пропуску. Опционально можно разрешить «возврат в течение X минут» для перевески.
- **Многоразовый:** любое число въездов в интервале (на Радонежском — от 2 дней до 1 месяца).
- **Постоянный:** без конца, закрывается вручную; напоминание о ревизии раз в N месяцев.
- **Окно прибытия** (обязательно для грузовых, если включено политикой):
  - въезд разрешён с `начало − early_tolerance`;
  - после `конец + late_tolerance` — по политике: красный, или жёлтый с запросом арендатору.
- **Истёк срок, пока машина внутри:** выпускать всегда; визит помечается «пребывание после окончания пропуска»; уведомление. Аналог «В просроченные» в PASS24 — правильное поведение.
- **Рабочее время комплекса:** параметр объекта. Въезд вне рабочего времени — по политике, с исключениями (X5 24/7).
- **Норматив времени на территории** по цели или категории (например, разгрузка 90 мин):
  - уведомление арендатору и админу о превышении;
  - **без блокировки других пропусков арендатора** — в PASS24 одна фура замораживала все пропуска компании.

## 4. Номера

- Нормализация:
  - верхний регистр;
  - кириллические АВЕКМНОРСТУХ → латинские (как в PASS24);
  - удаление пробелов, тире и точек.
- Хранятся исходный номер, нормализованный номер и страна.
- Российские форматы: `А999АА 777`, `А999 777`, `9999АА 777`, `А9999 777` (регион из 2–3 цифр).
- Иностранные: справочник масок с примерами — BY `1234AB7`, KZ `123ABC02`, TJ `1234AB01`, UZ `01A123BC`. Неизвестный формат принимается с пометкой «не распознан».
- Поиск — по подстроке нормализованного номера, в том числе по цифрам («524»).
- Дубли: запретить два активных пропуска на один номер у одного арендатора с пересекающимися окнами; разрешить у разных арендаторов (одна фура везёт разным) с предупреждением.

## 5. Редактирование и история

- Пропуск можно редактировать в любом статусе, кроме `used` и `cancelled`. Меняются только переданные поля.
- Номер у машины на воротах исправляется правом `pass.edit` с причиной.
- Нельзя сдвигать в прошлое начало уже начавшегося пропуска — это единственная временная проверка при правке.
- Журнал: каждая правка — запись «поле: было → стало, кто, причина».
- Названия арендатора, КПП и категории в Visit и GateDecision — снимок на момент события.

## 6. Согласование

- Политика по (роль создателя, тип пропуска, арендатор): авто / согласовать / запрещено.
- Карточка согласования показывает все поля будущего пропуска, в том числе конец срока.
- «Одобрить с изменениями» — изменённые поля видны арендатору.
- Если ответа нет за X часов — эскалация или авто-отклонение (настройка).

## 7. Исключения (обязательные для Радонежского)

## 8. Крайние случаи — что должна делать система

| Ситуация | Поведение |
|---|---|
| Машина приехала без пропуска | Жёлтый «нет пропуска» + «Запросить» → арендатор одобряет → зелёный. Без ответа — не пускать |
| Машина выезжает, въезд не отмечен | Найти пропуск; «Выпустить с отметкой» с причиной; уведомление админу |
| Машина выезжает, пропуск закрыт или просрочен | Выпустить, пометить, уведомить |
| Нажали «Впустить» по ошибке | «Отменить» в течение 2 минут; дальше — только админ с причиной |
| Квота полная, машина ждёт | Жёлтый со счётчиком; арендатору push «машина ждёт»; при выезде любой машины арендатора — сигнал на пост «можно впускать» |
| Фура приехала на КПП-1 | Синий «на КПП-2»; событие `wrong_gate` |
| Пешеход на КПП-2 | Синий «пешеходы — через КПП-1» |
| Номер в пропуске с опечаткой | Поиск по похожим номерам («отличается 1 символ»); исправление со старшим смены |
| Арендатор заблокирован, машина внутри | Выезд разрешён всегда; въезд — по режиму блокировки |
| Договор арендатора закончился | Новые пропуска запрещены; постоянные пропуска не действуют после даты; предупреждение за 30 дней |
| Одна машина работает на двух арендаторов | Два пропуска у разных арендаторов; при въезде охранник выбирает, к кому едет; квота — того, к кому |
| Пропал интернет на посту | Работа по кэшу: пропуска на сутки, квоты по последним данным плюс локальные события; синхронизация потом; конфликты — админу |
| Охранник не может найти по цифрам | Поиск по марке, по арендатору, по части фамилии водителя |
| Смена часового пояса или перевод часов | В РФ сейчас перевода нет, но хранить в UTC и пояс брать из базы tz |
