# Недостатки PASS24.online и как сделать лучше

Каждый пункт найден на живом стенде `integraciya74.pass24online.ru` (август–октябрь 2026) или в документах вендора. Ссылки вида [§9.7] ведут в `../reference/pass24_выдержки_базы_знаний.md` (там только часть разделов), [скрин NN] — в каталог скринов v1.8.

Критичность: 🔴 ломает работу или данные · 🟠 обходной путь или регулярная боль · 🟡 неудобство.

## A. Модель данных и правила

| # | Проблема в PASS24 | Последствие | Как у нас |
|---|---|---|---|
| A1 🔴 | **Лимит висит на адресе** (или на пользователе: «лимит активных пропусков» [§9.8]). Понятия «арендатор» и «группа транспорта» нет | Чтобы раздельно считать легковые и грузовые, арендатору заводят 2 адреса; старые 82 пропуска ДНС пришлось оставлять на переименованном адресе; пропуск с неверным типом на «чужом» адресе — только пересоздать | Квота = правило «арендатор × группа категорий × зона», независимое от адресов (`04_доменная_модель.md`) |
| A2 🔴 | Общий лимит «активных пропусков» считает **выданные пропуска на пользователя**, а не машины внутри и не компанию | У арендатора с тремя логистами квота втрое больше; заказанные заранее пропуска съедают места | Считаем **присутствие** (въехала и не выехала); заказанные пропуска лимит не занимают |
| A3 🔴 | **Фильтр КПП = адреса И типы транспорта**; пустой список = «не фильтровать» [§3.5] | КПП с типами не видит пешеходов (у них нет типа) [скрин 107–109]; на посту с пешеходами и машинами нужны две учётки в двух браузерах | Маршрут — отдельное правило «категория/участник → разрешённые КПП»; пешеход — тип участника, а не «машина без типа» |
| A4 🔴 | **Несколько КПП у сотрудника дают пересечение**, а не объединение | Добавили охраннику второй пост — он видит ноль пропусков | Пост охранника = устройство КПП; видимость — все пропуска объекта, а КПП влияет только на вердикт «ваш / не ваш КПП» |
| A5 🟠 | Нельзя отличить «пропуска нет» от «пропуск есть, но не на этот КПП» — чужие пропуска просто скрыты | Охрана говорит водителю «пропуска нет» при валидном пропуске | Показываем все пропуска; чужой КПП — красная плашка «направьте на КПП-2» и событие в журнале |
| A6 🟠 | Тип пропуска определяется длительностью интервала; селектор типа скрыт, пока максимальные сроки = 0; `0` = ноль часов [§5.1] | Полдня диагностики «Выбранный тип пропуска запрещён» | Тип выбирается явно; «без ограничения» — отдельный переключатель; ошибка называет настройку |
| A7 🟠 | Нет временных окон и слотов. Начало пропуска охрана не проверяет системно | Правило «раньше времени не пускать» охрана выполняет вручную, сверяя московское время | Временное окно пропуска с допуском «−X мин / +Y мин» проверяется при въезде автоматически |
| A8 🟠 | Нет мягких лимитов и сверхлимитных начислений | ДЛ-Транс по договору может брать места сверх 15/7 за 67/233 ₽ в сутки — система или блокирует, или не считает | Режимы квоты: жёсткий / мягкий с тарифом / информирующий; отчёт для счёта |
| A9 🟠 | Нет исключений (служебный автобус, 24/7, руководство) | Делается «постоянными пропусками» и устными договорённостями | Правила-исключения с приоритетом и основанием |
| A10 🟠 | **Переименование адреса переписывает историю** во всех прошлых пропусках [§3.3] | При смене арендатора бокса журнал заездов становится ложным | Снимок названий в каждой записи журнала; ссылка — только для навигации |
| A11 🟡 | Договор арендатора нигде не хранится; лимиты не связаны с пунктами договора | Каждую цифру приходится искать в скане | Карточка договора: PDF, сроки, пункты-основания у каждой квоты, напоминание об окончании |
| A12 🟡 | Справочник типов транспорта на уровне объекта, дефолт «Легковой» подставляется всегда | На логоцентре поток фур, весь массив уезжает в «Легковой» | Нет дефолта категории (обязательный выбор), либо дефолт задаёт арендатор (например, «фура» для X5) |
| A13 🟡 | Удаление КПП и типов транспорта без подтверждения и без показа ссылок | Случайные удаления | Мягкое удаление, показ «используется в N пропусках и M правилах» |

## B. Пропуска и редактирование

| # | Проблема | Последствие | Как у нас |
|---|---|---|---|
| B1 🔴 | **Любая правка пропуска молча меняет тип транспорта на «Легковой»** — у администратора и у охраны [§9.7, скрины 140–145] | Фура выпадает из КПП-2, «пропуска нет» | Редактирование = PATCH только изменённых полей; форма блокируется до загрузки; журнал «было → стало» |
| B2 🔴 | После наступления начала пропуск не сохраняется вообще: сервер требует «начало ≥ сейчас» при каждом сохранении, а поле начала заблокировано [§9.7] | Опечатку в номере у машины на воротах не исправить — только перевыпуск | Валидация «не в прошлом» только для изменённого поля начала; номер и комментарий правятся всегда с причиной |
| B3 🔴 | **«ДОБАВИТЬ ГОСТЯ» потерял вторую машину** (11.08.2026, тост «сохранено») [скрины 166–168] | Оформили две, в системе одна | Пакет = N пропусков, итог «создано N из N», построчные ошибки |
| B4 🟠 | Импорт файлом: один столбец номеров, один тип на файл, тип надо выбирать **после** загрузки, марки не импортируются, 500 строк | «Один файл — один тип» объясняется арендаторам в инструкции; ошибки типа | Вставка из буфера или Excel с колонками «номер · категория · марка · водитель · время», предпросмотр с подсветкой ошибок |
| B5 🟠 | В карточке разового запроса не виден конец срока [скрин 130] | Согласующий не знает, до какого часа даёт доступ | Карточка согласования показывает все поля будущего пропуска |
| B6 🟠 | Нельзя поправить заявку при одобрении — только одобрить или отклонить | Ошибку типа арендатора не исправить: отклонить и ждать переоформления | «Одобрить с изменениями» с записью в журнал |
| B7 🟡 | Терминология двоится: «Разовый» / «Одноразовые» / «одноразового», «многоразовый» = временный + постоянный | Путаница в обучении | Единый словарь терминов |
| B8 🟡 | Тост «успешно сохранено» при подменённом значении (вес сортировки −20 → 10) [скрины 35–36] | Нельзя доверять подтверждению | Никакой молчаливой подмены: либо отказ с причиной, либо «изменено на X, потому что Y» |
| B9 🟡 | Номер проверяется по чёрному списку запросом на каждый символ, без дебаунса [скрин 64] | Лишняя нагрузка | Дебаунс 300 мс |
| B10 🟡 | Маска ГРЗ только российская (4 формата); иностранные номера только при выключенной проверке | Казахские и белорусские фуры при включённой проверке не оформить | Справочник форматов по странам + свободный ввод с пометкой «иностранный» |

## C. Охрана

| # | Проблема | Последствие | Как у нас |
|---|---|---|---|
| C1 🔴 | **Нет рабочей настройки прав охраны:** «Только статус» не работает (охранник правит всё), «Запрещён» гасит кнопку «Приехал» [§3.5.1, скрин 146] | Пост либо бесконтрольный, либо бессильный | Отдельные права: `visit.check_in/out` и `pass.edit` |
| C2 🔴 | «Заблокирован» (превышение времени) **не запрещает проезд** — кнопки активны [скрины 160, 170] | Охранник впустит, не заметив красную строку | Вердикт «нельзя» блокирует основную кнопку; пропустить можно только «исключением» с причиной и правом |
| C3 🟠 | Квота «на территории» не видна охране: ни счётчика по арендатору, ни причины отказа | Охрана не может объяснить водителю «ждите, доки заняты» | Плашка «ДНС грузовые: 25/25 — ждать выезда» и табло заполненности |
| C4 🟠 | Время в списке московское, а охрана живёт по местному | Ручной пересчёт +2 часа | Местное время объекта везде, с подписью пояса |
| C5 🟠 | Вход по e-mail и паролю, сессии вылетают, профиль браузера общий | Отдельная программа «Что делать если» с копированием пароля | Устройство поста привязывается к КПП один раз (токен + QR); охранник входит PIN-кодом смены |
| C6 🟠 | Поиск надо очищать вручную, иначе «пропали все заявки»; галочки фильтров легко сбить | Главная причина обращений охраны | Поиск по цифрам номера, автоочистка после действия, фиксированный рабочий вид без лишних фильтров |
| C7 🟠 | Нет потока «машина на воротах без пропуска» | Охрана звонит арендатору или администратору | Кнопка «Запросить пропуск» → push ответственному арендатора → «Одобрить» в одно касание → охрана видит пропуск |
| C8 🟠 | Выезд без пропуска или без отметки въезда, повторная отметка — нет сценариев | Всё через звонок администратору | Сценарии «выезд без пропуска» и «въезд не отмечен» с причиной и уведомлением админа |
| C9 🟡 | Шлагбаум — отдельная ручная операция после кнопки | Двойная работа, можно забыть | Интеграция с реле шлагбаума: «Впустить» открывает (позже) |
| C10 🟡 | Задвоение строки в списке охранника [скрин 135] | Путаница | Стабильные ключи списка, тест на дубли |

## D. Арендатор

| # | Проблема | Последствие | Как у нас |
|---|---|---|---|
| D1 🔴 | **Нет веб-кабинета арендатора.** Пользователь = мобильное приложение. Обход: арендатор работает как «сотрудник» с урезанной группой прав | Логист переписывает номера из письма в телефон | Полноценный веб-кабинет + PWA |
| D2 🟠 | Пользователь, заведённый админом, — не учётка, пока человек сам не зарегистрируется в приложении; SMS-приглашения нет (документация врёт) | Импорт сотни арендаторов не создаёт ни одной рабочей учётки | Приглашение по SMS или e-mail со ссылкой, статус «приглашён / активен» |
| D3 🟠 | Арендатор не видит своей квоты и того, кто сейчас внутри | Звонки на КПП | Виджет «на территории: легковые 12/30, грузовые 20/25» + список |
| D4 🟠 | Экспорт истории — письмом, ссылка живёт 24 часа, максимум 31 день | Неудобно, теряется | Скачивание сразу (CSV/XLSX), любой период, сохранённые отчёты |
| D5 🟡 | ФИО из админки не подтягивается в профиль («Не указано») [скрин 122] | Мелочь, но выглядит сломанным | Один профиль |
| D6 🟡 | Реклама «Специальные предложения» в приложении арендатора [скрин 116] | Чужой маркетинг в инструменте заказчика | Никакой рекламы |
| D7 🟡 | Страница приглашения без адреса объекта, схемы, номера КПП, телефона поста; ссылка без срока и без авторизации | Водитель не знает, куда ехать; у кого ссылка — у того доступ | Страница водителя: QR, номер, **на какой КПП ехать**, карта/схема, окно времени, телефон; токен со сроком |

## E. Администрирование и надёжность

| # | Проблема | Последствие | Как у нас |
|---|---|---|---|
| E1 🔴 | **Часовые пояса:** форма подставляет время браузера, сервер трактует как МСК; настройки пояса объекта нет [§16.5] | Арендаторы ставят время на 2 ч меньше; удалённый админ из Техаса не может создать пропуск «на сейчас» | Пояс — свойство объекта; все формы и экраны в нём |
| E2 🟠 | Ошибки без причины: «Выбранный тип пропуска запрещён» при двух независимых причинах; бэкенд при этом умеет отдавать детали (FastAPI) [скрин 59] | Часы диагностики | Ошибка = что не так + какая настройка + ссылка на неё |
| E3 🟠 | Новая дочерняя группа прав наследует полные права родителя («Администраторы») | Охранник получает права админа | Новая роль = ноль прав, шаблоны ролей |
| E4 🟠 | Право «доступ к модулю» влияет на выпадающие списки в чужих формах | Нельзя скрыть «Сотрудники» от охраны и при этом назначить ей группу | Права на действия, а не на «модули-экраны» |
| E5 🟠 | Документация расходится с продуктом: роли, SMS, блокировка адреса, режимы одобрения | Решения на неверных данных | Документация из тех же текстов, что UI; встроенная справка |
| E6 🟡 | Список адресов в выпадающем меню — первые 100 | Неудобно при сотнях боксов | Поиск по всем, сначала недавние |
| E7 🟡 | Удаление закрытых пропусков через 30 дней (по документации) | Теряется история | Хранение настраиваемо, по умолчанию 3 года (уточнить по 152-ФЗ) |
| E8 🟡 | Блокировка адреса, по формулировке, бьёт и по уже выданным пропускам, а по документации — нет | Неясно, можно ли блокировать днём | Явные режимы блокировки: «новые пропуска запрещены» / «въезд запрещён» / «полная» |

## Что в PASS24 хорошо и стоит взять

- Трёхзначный режим «Разрешить / Запретить / По запросу» для создания пропусков разными ролями.
- Нормализация ГРЗ: кириллица в латиницу, верхний регистр, без пробелов. Хранить нормализованный номер отдельно и искать по нему.
- История событий пропуска с автором и временем.
- Фильтр «на территории» + «тип: автомобиль» — мгновенный ответ «сколько машин внутри».
- Иконки опций (Разгрузка, Погрузка) прямо в списке.
- Поле «Минуты» у опции — норматив времени на территории (у нас: норматив простоя по категории или цели визита с уведомлением о превышении).
- Сканер QR как способ въезда.
- Встроенный AI-помощник по платформе.
